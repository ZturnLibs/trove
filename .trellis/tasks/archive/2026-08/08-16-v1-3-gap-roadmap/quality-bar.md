# 体验极致契约（不极致不退出）

本文件适用于 `08-16-v1-3-gap-roadmap` 下**全部子任务**。任一子任务在 `task.py archive` 前必须通过下列门禁；未通过则继续迭代，不以「功能可用」为完成标准。

## 1. 极致的定义（本项目）

| 维度 | 极致标准 | 反例（不得归档） |
| --- | --- | --- |
| **记录成本** | 核心动作 ≤3 次键击或 1 次明确手势；有 sensible default | 必须开详情页才能完成的捕获 |
| **切换成本** | 不离开当前页可完成 80% 高频操作；全局快捷键覆盖 | 为改一个字段强制换页 |
| **找回成本** | 任意状态任务/记忆在搜索 + 专用视图中 ≤2 步找到 | 推迟/等待后「消失找不到」 |
| **维护成本** | 批量/状态变更有确认 + 撤销；文案温和无 guilt-trip | 红色 OVERDUE 羞辱式徽章 |
| **可信程度** | 能力不夸大；失败有降级路径；数据可导出/迁移 | 静默失败、状态不一致 |
| **键盘** | 列表内完整键盘模型；快捷键写入 keyboard-shortcuts.md | 只能鼠标操作的新流程 |
| **一致性** | 同一概念全应用同一词、同一图标、同一筛选语义 | Today 与 Tasks 对「活跃」解释不同 |
| **性能** | 万级数据首屏 <200ms；交互无 perceptible jank | 全量渲染、阻塞主线程 |
| **可逆** | 破坏性操作进 recent-actions 栈（≤5） | 误点无法撤销 |
| **空状态** | 每个新视图有引导 + 下一步动作 | 空白页无说明 |

## 2. 子任务归档门禁（Checklist）

每个子任务 `trellis-check` 前必须全部为真：

- [ ] PRD 全部 AC 勾选，且**无已知 P1 体验缺陷**
- [ ] 新增/变更交互已更新 `docs/keyboard-shortcuts.md` 或对应 UI 文档
- [ ] 空状态、错误态、权限降级文案符合 `docs/empty-states-and-permissions.md` 语气
- [ ] Rust 单测覆盖新 domain 规则边界；前端 vitest 覆盖新 hook/解析逻辑
- [ ] 手动走通「新用户第一次用」与「老用户升级迁移」两条路径
- [ ] 与父任务 `quality-bar.md` 九维对照，弱项有 documented follow-up 或本迭代补齐

## 3. 与竞品的对标方式

不追求功能数量对齐，追求**场景完成度**：

1. 选定 3 个对标场景（写入子任务 `design.md`）
2. 录制或逐步描述 Trove 路径 vs 竞品路径（步数、键击数）
3. Trove 步数 ≤ 竞品，或步数相同但**更可预测/可撤销**方算极致

## 4. 迭代纪律

- **不拆「半成品」归档**：MVP 可小，但已交付切片必须端到端可验收
- **设计债即时还**：临时 UI 允许存在 ≤1 个迭代，必须在 `implement.md` 标注偿还任务
- **用户可见命名冻结前**：推迟/等待/重点等术语在 `design.md` 定稿，全应用统一
