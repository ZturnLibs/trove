# 一站式个人工作台开发规划

## 1. 文档目的

本文档将产品第一版功能拆分为可独立开发、演示和验收的阶段，用于控制范围、安排依赖并判断 `v1.0` 是否达到可发布状态。

规划基于以下已经确认的产品边界：

- 采用 Tauri Web 跨端桌面方案，首批目标平台为 macOS 和 Windows，Linux 后置。
- 面向个人用户，不包含团队协作。
- 本地优先，核心功能无需登录和网络连接。
- 记忆模块用于保存短小、可检索的信息片段，不发展为完整文档系统。
- 第一版包含任务、一次性和周期性提醒、记忆、文本剪切板、统一搜索。
- 暂不包含移动端、云同步、AI、插件市场和复杂自动化。

## 2. 第一版目标

第一版要完成的核心闭环是：

```text
快速捕获 -> 安排任务或提醒 -> 到时通知 -> 完成或稍后处理
          -> 保存为记忆 -> 搜索找回
剪切板采集 -> 再次使用、转为记忆或任务
```

产品默认首页为“今日”，一级入口包括今日、收件箱、任务、记忆和剪切板。提醒作为任务的附属能力和独立的时间事件存在，不单独建设复杂日历模块。

## 3. 开发原则

1. 每一期结束时都应产出可以运行和演示的应用，不以仅完成底层代码作为交付结果。
2. 先建立数据可靠性和提醒可靠性，再增加效率功能。
3. 任务、记忆、剪切板采用清晰的数据边界，通过“转换”操作联动，不合并成含义模糊的通用对象。
4. 所有核心功能必须离线可用，不依赖远程服务。
5. 涉及剪切板和系统权限时，坚持最小权限、用户可见、随时可停用。

## 4. 阶段总览

| 阶段 | 版本建议 | 核心结果 | 参考周期 |
| --- | --- | --- | --- |
| 阶段 0：应用基础 | `0.1.0` | 可运行的 macOS、Windows 应用骨架和可靠的本地数据层 | 1 周 |
| 阶段 1：任务闭环 | `0.2.0` | 可以捕获、管理和完成日常任务 | 2 周 |
| 阶段 2：提醒系统 | `0.3.0` | 一次性、周期性提醒和周期任务可靠运行 | 2 周 |
| 阶段 3：记忆与搜索 | `0.4.0` | 信息片段能够保存、转换和统一检索 | 1.5 周 |
| 阶段 4：剪切板 | `0.5.0` | 文本剪切板能够安全采集和快速复用 | 2 周 |
| 阶段 5：整合与发布 | `1.0.0` | 数据可恢复、权限清晰、核心流程稳定 | 1.5 至 2 周 |

原参考周期按一名全职工程师估算。调整为 macOS、Windows 双平台后，必须在阶段 0 验证系统差异并重新估算，原周期不再作为双平台交付承诺。

## 5. 阶段 0：应用基础

### 目标

建立后续各模块共用的跨端桌面运行环境、本地数据能力和基础交互框架，尽早验证两个首批平台的系统权限及后台运行方式。

### 开发范围

- 创建 Tauri、React、TypeScript、Tailwind CSS、Rust 工程及 macOS、Windows 开发、测试和打包流程。
- 建立主窗口、托盘入口、快捷窗口和基础导航框架。
- 建立本地数据库、数据库迁移和数据访问层。
- 建立统一的实体 ID、时间、软删除和归档约定。
- 建立应用设置存储和日志机制，日志不得记录用户正文及剪切板内容。
- 分别验证 macOS、Windows 的系统通知、全局快捷键、开机启动和后台运行能力。
- 确定直接粘贴所需权限、平台差异和未授权降级方案。
- 建立最基础的自动化测试和持续集成检查。

### 暂不包含

- 完整业务页面。
- 正式的数据导入导出。
- 剪切板内容采集。
- 登录、云端服务和自动更新服务。

### 交付与验收

- 应用能够启动、退出，并可从系统托盘重新打开主窗口。
- 应用重启后，测试数据仍然存在。
- 数据库可以通过版本迁移升级，不需要删除旧数据。
- 全局快捷键冲突时能够提示并允许重新设置。
- 通知未授权时应用不会崩溃，并能引导用户前往系统设置。

## 6. 阶段 1：任务闭环

### 目标

让用户可以在应用内或任意应用上方快速记录任务，并在今日、收件箱和任务列表中完成日常管理。

### 开发范围

#### 任务数据

- 标题、说明、状态、优先级、截止日期和截止时间。
- 所属清单、多个标签、创建时间、完成时间和排序值。
- 状态包含待办、已完成和已归档。
- 新任务默认进入收件箱。

#### 页面与交互

- “今日”视图：逾期任务、今日任务和今日已完成任务。
- “收件箱”视图：尚未整理的新任务。
- “任务”视图：按清单查看全部任务。
- 任务详情的创建、编辑、完成、取消完成、归档和删除。
- 按日期、状态、优先级、标签和清单筛选。
- 列表内手动排序。
- 全局快速记录窗口，默认创建任务。
- 基础键盘操作，包括提交、取消和列表选择。

### 暂不包含

- 提醒通知和重复规则。
- 多层子任务、任务依赖和附件。
- 甘特图、日历月视图、工时统计和生产力评分。
- 自然语言日期解析；日期首先通过明确控件选择。

### 交付与验收

- 用户可通过全局快捷键在任意应用上方创建任务。
- 创建的任务立即出现在收件箱；带今日截止日期时也出现在今日视图。
- 完成、恢复、归档和删除操作在应用重启后保持正确。
- 今日视图始终将逾期未完成事项放在今日事项之前。
- 筛选和排序不会修改任务自身的业务数据。

## 7. 阶段 2：提醒系统

### 目标

实现可靠的一次性提醒、周期提醒和周期任务，使应用在重启、休眠恢复和短暂退出后仍能正确处理通知。

### 开发范围

#### 提醒类型

- 任务提醒：绑定任务，一个任务可以有多个提醒。
- 独立提醒：不要求绑定任务。
- 一次性提醒：指定日期和时间。
- 周期提醒：每天、工作日、每周指定星期、每月指定日期、每隔若干天或周。
- 可选重复结束日期。

#### 周期任务

- 任务可设置独立的重复规则。
- 完成当前周期任务后生成下一实例。
- 每个实例保留独立的完成状态和时间。
- 支持跳过当前实例，不影响之后的计划。

#### 通知操作

- 完成关联任务或独立提醒。
- 稍后 10 分钟、1 小时、明天或自定义时间。
- 从通知打开对应详情。
- 在今日视图展示当天独立提醒。

#### 可靠性规则

- 应用恢复运行时，一次性提醒若已错过则补发一次。
- 周期提醒错过多次时只处理最近一次，不连续补发历史通知。
- 提醒触发和用户操作均记录状态，避免重复通知。
- 保存原始时区，明确处理系统时区变化和夏令时。

### 暂不包含

- 完整日历视图和日历账户同步。
- 根据地点、邮件或其他应用事件触发提醒。
- 任意表达式级别的复杂重复规则。

### 交付与验收

- 一次性提醒能够准时发送系统通知。
- 用户可从通知完成任务或设置稍后提醒。
- 应用在提醒前退出并在提醒后重新启动时，只补发一次。
- 电脑休眠跨过提醒时间后，恢复时能够正确处理提醒。
- 周期任务完成后生成正确的下一实例，且保留历史实例。
- 工作日、跨月和时区变化场景具备自动化测试。

## 8. 阶段 3：记忆与统一搜索

### 目标

让用户保存短小信息片段，并能通过一个搜索入口找回任务、提醒和记忆。

### 开发范围

#### 记忆

- 标题、正文、多个标签、置顶状态、创建和更新时间。
- 正文支持基础 Markdown 编辑和展示。
- 自动识别可点击的网址。
- 创建、编辑、置顶、归档、删除和复制。
- 从快速记录窗口直接创建记忆。
- 记忆一键转为任务，原记忆默认保留并记录来源关系。

#### 统一搜索

- 搜索任务标题和说明、独立提醒标题、记忆标题和正文。
- 按内容类型分组展示结果。
- 支持类型、标签和状态筛选。
- 支持键盘选择并打开结果。
- 提供独立的全局搜索快捷键。

### 暂不包含

- 富文本编辑、附件、图片笔记和网页正文抓取。
- 多级知识目录、双向链接和知识图谱。
- 语义搜索、向量数据库和 AI 摘要。

### 交付与验收

- 用户可在快速记录窗口中切换任务、提醒和记忆类型。
- 修改任务或记忆后，搜索索引能够及时更新。
- 搜索结果可以明确区分内容类型，并可直接打开详情。
- 将记忆转为任务后，任务内容正确且原记忆不会意外丢失。
- 中等数据量下的搜索交互无明显阻塞；具体性能基线在技术设计阶段确定。

## 9. 阶段 4：文本剪切板

### 目标

安全地记录文本剪切板历史，让用户快速查找、再次使用，并与任务和记忆形成转换闭环。

### 开发范围

#### 采集与存储

- 监听系统文本剪切板变化。
- 保存文本、复制时间、收藏状态、使用次数和最近使用时间。
- 系统能力允许时记录来源应用；无法可靠获取时允许为空。
- 相邻重复内容去重。
- 默认自动过期，可配置保留天数和最大记录数量。
- 收藏条目不参与自动过期。

#### 使用方式

- 浏览和全文搜索剪切板历史。
- 再次复制到系统剪切板。
- 在用户授予辅助功能权限后支持直接粘贴；未授权时降级为再次复制。
- 收藏、取消收藏、单条删除和清空非收藏记录。
- 将条目保存为记忆或转为任务。
- 从菜单栏或全局快捷键打开剪切板窗口。

#### 隐私控制

- 一键暂停和恢复记录。
- 支持排除指定应用。
- 默认排除已知密码管理器，并允许用户调整排除列表。
- 不采集系统标记为暂态、机密或禁止记录的内容。
- 在设置中明确说明无法仅凭文本内容准确识别所有密码、验证码和密钥。
- 所有剪切板数据只保存在本地，不写入日志。

### 暂不包含

- 图片和文件剪切板。
- 跨设备剪切板同步。
- 对剪切板内容进行联网识别或 AI 分类。
- 多片段组合粘贴和复杂自动化动作。

### 交付与验收

- 复制普通文本后，记录能及时出现在历史列表中。
- 连续复制同一内容不会产生大量重复条目。
- 暂停记录、排除应用和自动过期规则均实际生效。
- 未授予辅助功能权限时，再次复制功能仍可正常工作。
- 收藏条目不会因过期清理而删除。
- 剪切板条目可以正确转为任务或记忆，并出现在统一搜索中。
- 清空操作明确提示保留与删除范围。

## 10. 阶段 5：整合与发布

### 目标

补齐数据恢复、权限说明、异常状态和端到端测试，使应用达到可以长期保存个人工作数据的质量标准。

### 开发范围

- 统一今日、任务、提醒、记忆和剪切板的交互与视觉状态。
- 完善空状态、加载状态、权限缺失、数据损坏和磁盘空间不足提示。
- 增加完整 JSON 导出和导入。
- 增加自动本地备份、备份轮转和手动恢复。
- 完善快捷键设置、冲突提示和恢复默认值。
- 增加开机启动选项及后台运行说明。
- 检查菜单栏、主窗口和快速窗口之间的状态同步。
- 完成端到端测试、性能检查和应用打包签名。
- 准备隐私说明、数据存储说明和首次启动权限引导。
- 根据发布渠道决定是否加入自动更新；此项不阻塞核心功能验收。

### 交付与验收

- 任务、提醒、记忆和剪切板的核心流程可以在完全断网时完成。
- 导出后能够在新的空数据库中恢复完整业务数据。
- 自动备份失败时有可见提示，不会静默丢失保护能力。
- 数据库升级前先生成可恢复备份。
- 应用重启、系统重启和睡眠恢复后，数据与提醒状态一致。
- 未授予通知或辅助功能权限时，应用提供明确的降级能力。
- 完成连续使用和异常退出测试，不出现重复提醒或明显数据丢失。

## 11. `v1.0` 发布门槛

只有同时满足以下条件，第一版才视为完成：

1. 用户能通过全局快捷键创建明天到期的任务。
2. 到达提醒时间后能收到系统通知，并能完成或稍后处理。
3. 周期任务完成后能生成正确的下一实例。
4. 用户能搜索并重新使用历史剪切板文本。
5. 剪切板条目能保存为记忆或转为任务，并被统一搜索找到。
6. 应用重启、系统重启、休眠恢复和短暂退出不会导致核心数据丢失或提醒重复。
7. 所有核心功能在断网时正常工作。
8. 用户可以导出、备份和恢复自己的全部业务数据。
9. 用户可以暂停剪切板记录，并清楚了解各项系统权限的用途。
10. 不存在会造成任务、提醒或记忆永久丢失的已知高优先级缺陷。

## 12. 跨阶段工作

以下工作不应推迟到最后一期一次性处理：

- 数据库迁移和备份兼容性。
- 提醒调度、重复计算和时区相关测试。
- 快捷键优先的键盘可用性。
- macOS、Windows 的通知、直接粘贴和开机启动权限测试。
- 用户正文、剪切板内容和日志的隐私审查。
- 空状态、错误状态和权限拒绝状态。
- 常用操作的性能监控，但监控数据不得包含用户内容。

## 13. 风险与应对

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 后台调度受系统休眠和退出影响 | 提醒遗漏或重复 | 阶段 0 做能力验证；提醒状态落库；启动和唤醒时重新计算 |
| 周期规则边界复杂 | 跨月、时区变化时生成错误 | 限定首版规则；使用成熟日期时间能力；建立边界测试集 |
| 剪切板涉及敏感数据 | 用户隐私风险 | 本地存储、排除应用、暂停记录、自动过期、明确能力边界 |
| 直接粘贴权限或平台能力不足 | 无法自动粘贴 | 将“再次复制”作为始终可用的降级流程 |
| 全局快捷键与其他应用冲突 | 高频入口不可用 | 支持检测、修改和恢复默认快捷键 |
| 功能不断扩张 | 第一版延期 | 以本文件的“暂不包含”和发布门槛作为范围基线 |
| 本地数据库损坏或升级失败 | 个人数据丢失 | 迁移前备份、备份轮转、导出恢复和故障测试 |

## 14. 第一版之后的候选方向

第一版之后先继续强化桌面端的快捷操作、信息捕获、个人复盘和自动化。日历不是核心高频功能，手机随手记录也不需要提前建设，两者仅作为满足启动条件后的远期候选。

详细方案参见[第一版之后的迭代详细设计](./post-v1-iteration-design.md)。以下内容不应提前并入第一版：

- 图片和文件剪切板。
- 日历账户集成和日历视图。
- iPhone 端和跨设备同步。
- 端到端加密的云备份。
- 附件和更完整的 Markdown 能力。
- 可配置命令面板、文本模板和轻量自动化。
- 插件机制。
- 本地或明确授权后的 AI 辅助整理与检索。

候选功能应根据第一版真实使用频率、失败流程和用户反馈排序，不能仅按实现便利性进入开发。
