# 第一版应用菜单设计

## 1. 文档目的

定义 `v1.0` 桌面端全部菜单表面：系统菜单栏、托盘菜单、列表/详情上下文菜单，以及与快捷键、窗口状态的启用规则。

本文与[UI 布局与交互](./ui-layout-interaction.md)配套；窗口与托盘职责以该文档为准。功能范围不超出[第一版开发规划](./development-roadmap.md)。

## 2. 菜单表面总览

| 表面 | 形态 | 职责 |
| --- | --- | --- |
| 应用菜单栏 | 原生 Menu Bar | 标准桌面操作、导航、当前实体动作、窗口与帮助 |
| 托盘菜单 | 原生 Tray Menu | 主窗隐藏时的短入口；暂停采集；退出 |
| 上下文菜单 | WebView 内（Radix） | 列表行、详情、空白处的就地操作 |
| 行内「⋯」菜单 | WebView 内 | 与上下文菜单同源动作，便于鼠标发现 |

原则：

1. **同一动作同一语义**：菜单栏、托盘、上下文、按钮触发同一 Application 用例，校验与确认一致。
2. **原生优先承载全局**：退出、隐藏、标准编辑、窗口级命令走原生菜单，便于系统快捷键与可访问性。
3. **托盘保持短**：不复制完整任务管理；完整浏览回主窗。
4. **上下文跟焦点**：无选中实体时，「项目」类菜单项禁用，不静默空操作。
5. **`v1.0` 不做**：菜单栏今日面板、状态栏菜单内嵌 WebView 列表（见 `v1.1`）。

## 3. 应用菜单栏

### 3.1 平台结构差异

| 平台 | 结构 |
| --- | --- |
| macOS | 左侧为应用名菜单（关于、设置、隐藏、退出等），其后为「文件 / 编辑 / 显示 / 转到 / 项目 / 窗口 / 帮助」 |
| Windows | 无独立应用名菜单；「文件」含设置与退出；其余顶级菜单与 macOS 对齐 |

菜单文案默认中文；若系统语言为英文，可用英文平行文案（见文末对照表）。实现上菜单定义集中在 Rust，按 locale 选文案。

### 3.2 菜单项 ID 约定

所有可点击项使用稳定 ID（供 IPC 与测试），格式：`menu.<group>.<action>`。

示例：`menu.file.new_task`、`menu.item.complete`、`menu.tray.toggle_clipboard`。

产品显示名暂用「工作台」，正式品牌名确定后只改此菜单标题与关于框。

| --- | --- | --- | --- |
| 关于工作台 | `menu.app.about` | — | 打开设置「关于」或独立关于对话框 |
| — | | | |
| 设置… | `menu.app.settings` | `⌘,` | 显示主窗并打开 `/settings` |
| — | | | |

## 4. 托盘菜单

### 4.1 结构

```text
打开主窗口
快速记录…
剪切板历史…
─────────────────
下一条提醒
  （无）禁用，文案：「暂无即将到来的提醒」
  （有）单行摘要，最长约 40 字，超出省略
─────────────────
暂停剪切板记录  /  恢复剪切板记录     ← 互斥文案
─────────────────
设置…
─────────────────
退出工作台
```

### 4.2 项定义

| 项 | ID | 行为 |
| --- | --- | --- |
| 打开主窗口 | `menu.tray.open_main` | 显示 main，保持上次路由 |
| 快速记录… | `menu.tray.quick_capture` | quick capture |
| 剪切板历史… | `menu.tray.clipboard` | quick clip |
| 下一条提醒 | `menu.tray.next_reminder` | 有则打开详情；无则禁用 |
| 暂停/恢复剪切板记录 | `menu.tray.toggle_clipboard` | 切换采集；文案随状态 |
| 设置… | `menu.tray.settings` | 主窗设置 |
| 退出工作台 | `menu.tray.quit` | 真正退出 |

### 4.3 平台点击手势

| 平台 | 主按钮 | 次按钮 |
| --- | --- | --- |
| macOS | 打开托盘菜单（惯例） | — |
| Windows | 左键：打开主窗口 | 右键：托盘菜单 |

阶段 0 验证后若 macOS 需要「左键开主窗」，可改为：左键开主窗，右键或 ⌃ 点击出菜单；须在设置「通用」说明。

### 4.4 动态刷新

- 剪切板暂停态变化：立即更新托盘项文案。
- 「下一条提醒」：提醒调度变更、完成、稍后、启动协调后刷新；摘要**不得**写入系统日志。
- 托盘菜单不列出完整今日任务（留给 `v1.1` 菜单栏面板）。

## 6. 启用、确认与危险操作

| 规则 | 说明 |
| --- | --- |
| 无选中 | `menu.item.*` 与上下文实体项全部 disabled |
| 主窗隐藏 | 菜单栏在 macOS 仍可能属于应用；动作先 `show main` 再执行导航类命令 |
| quick 前置 | 「新建任务」等可只写数据不强制开 main；「显示 · 今日」等须 show main |
| 删除 / 清空 / 导入覆盖 | 必须确认对话框；菜单项文案带省略号 `…` |
| 直接粘贴 | capability 为 false 时 disabled，不隐藏，便于发现 |
| 阶段未交付 | 导入导出备份等菜单项：未实现前 **隐藏**（优于一排禁用） |

## 7. 快捷键归属

| 类型 | 归属 | 示例 |
| --- | --- | --- |
| 应用内导航与编辑 | 菜单栏加速键 | `⌘1`–`⌘5`、`⌘N`、`⌘,` |
| 系统级全局 | 全局快捷键设置 + 菜单项旁标注 | capture / search / clip / show main |
| 列表局部 | 不进菜单栏，仅文档与快捷键一览 | `j` `k`、`Space` 完成 |

同一动作只保留一个「用户可改」快捷键配置项；菜单显示的加速键与设置同步。完整定稿见[快捷键一览](./keyboard-shortcuts.md)。

全局快捷键与菜单加速键冲突时：全局键在其它应用上也生效；菜单加速键仅应用激活时生效。设置中分组展示，避免用户改一处漏一处。

## 8. 实现要点（Tauri）

1. 菜单定义在 Rust 侧构建（`tauri::menu`），点击后走已有 Command / Application 用例，**不**在前端各写一套。
2. 前端通过事件请求「刷新菜单启用态」：选中实体变化、暂停态变化、提醒摘要变化时，Rust 更新原生菜单与托盘。
3. WebView 上下文菜单用 Radix Menu；`onSelect` 调用与菜单栏相同的 typed IPC。
4. macOS `⌘Q` 与托盘退出调用同一 `app_quit`；关闭按钮与 `⌘W` 调用 `window_hide`。
5. Windows 需显式创建菜单栏并挂到主窗；quick 浮层可不挂完整菜单栏，避免窄窗噪音（动作仍可用快捷键与主窗菜单——应用激活时）。
6. 自动化测试：菜单 ID 稳定快照；关键路径用 WebdriverIO 触发菜单事件或直接调 command。

## 9. v1.0 明确不做

- 托盘或菜单栏内嵌今日任务完整列表 / WebView 面板
- 菜单内自然语言创建
- 业务级撤销/重做菜单（仅文本编辑撤销）
- 服务端账户、分享到网络、评分弹窗
- 插件菜单

## 11. 验收标准

1. macOS 应用菜单含关于、设置、隐藏、退出；`⌘Q` 退出进程，`⌘W` 仅隐藏窗口。
2. Windows 文件菜单可设置与退出；`Alt+F4` 隐藏主窗而不误杀后台（与文档一致）。
3. `⌘1`–`⌘5` 与「显示」菜单一致切换五入口。
4. 无选中时「项目」动作全部禁用；选中任务后可完成/删除。
5. 托盘可打开主窗、快速记录、剪切板；暂停文案随状态变化；退出与菜单栏退出等效。
6. 上下文菜单与「项目」菜单对同一实体动作结果一致。
7. 删除类菜单项均带确认；直接粘贴在无权限时禁用而非崩溃。
8. 全局快捷键与菜单栏标注在默认配置下一致，设置页可查。
