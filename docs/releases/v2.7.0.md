# Trove v2.6.2 → v2.7.0

让外部 Agent（编码助手、脚本、快捷指令）可以**闭环管理** Trove 任务：此前 CLI 只能创建和完成，现在查询、修正、回收全部可用。核心场景：从钉钉聊天等来源提取待办后，一条命令批量入库，建错了也能在命令行里直接修。

## 新增

- **CLI 完整任务管理**（`trove-cli`）：
  - 通用查询 `query tasks`（状态 / 清单 / 搜索词 / 截止区间 / 父任务 / 分页）与 `query lists`（清单 id / 名称 / 待办数）
  - `show <id>` 任务详情（完整备注、标签、父子关系）
  - `create task` 支持 `--list`（**按清单名称引用**）/ `--priority` / `--tag` / `--parent` / `--due-time`
  - `create-batch` 从 NDJSON 批量导入（上限 100 条/次，逐条隔离失败，返回逐条结果与 taskId）
  - `update`（部分字段更新，其余保持不变；`--clear-due` 显式清空截止）、`reopen` / `archive` / `delete`（强制显式子任务处置）/ `postpone` / `defer`
  - 安全约定：写操作一律 `--yes`；`--dry-run --json` 预览不触碰应用；文档见 `docs/cli.md`
- **Agent Skill**：`.opencode/skills/trove-cli/SKILL.md`，Agent 平台可即取即用（含钉钉聊天 → 批量任务 recipe）
- **开发实例隔离**：`pnpm tauri:dev` 使用独立 identifier `com.trove.dev`，与正式版同时运行互不干扰，开发不再污染真实任务数据

## 升级说明

- 无数据库 schema 变更，无数据迁移风险
- CLI 新命令需要**新版本应用**在运行才能执行（CLI 经应用落库，不直接读写 SQLite）；旧命令不受影响
- 开发者的本地 dev 数据将迁移到新目录 `~/Library/Application Support/com.trove.dev`（首次运行 dev 为全新空库；正式版数据位置不变）
